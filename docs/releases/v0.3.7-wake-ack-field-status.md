# v0.3.7 Wake Acknowledgement & Field Status Copy

Scope: GitHub prerelease candidate for field testing after the real-vehicle voice Q&A baseline. This release focuses on clearer in-car interaction feedback and more accurate user-facing status text while Redis/protobuf field coverage is still being verified.

## Why this release exists

The previous build still exposed old copy that described the app as a local development skeleton and said KWS/VAD/ASR were not connected. That is no longer accurate: the real microphone path now uses offline wake detection, VAD, Vosk ASR, NLU, and TTS. Field testing also showed that some vehicle data fields are not yet clearly attributable to reader bugs versus missing/unconfirmed Redis/protobuf data. The app now communicates that distinction instead of implying the voice stack is absent.

## User-visible changes

- Foreground notification now says the offline voice chain is connected and basic testing has passed, while some vehicle fields still need confirmation.
- Startup log now frames the current phase as in-vehicle Redis/protobuf interface verification.
- Unknown or unmatched utterances now respond with `没有听清请再说一遍` instead of the more technical `没有识别到有效指令`.
- In real microphone mode, after the wake phrase such as `小车小车`, the app replies `我在，请说` before listening for the command.
- The debug panel now distinguishes wake acknowledgement from the command listening state:
  - 已唤醒，正在提示
  - 请说指令

## Runtime behavior changes

- Real microphone mode plays a wake acknowledgement through TTS after KWS wake detection.
- The pipeline ignores a short post-acknowledgement audio window, currently 8 frames, to reduce the chance that the app records its own prompt as part of the user command.
- Existing read-only safety remains unchanged: real-vehicle mode still rejects vehicle-control mutations and Unity control actions.

## Validation

Validated locally with:

```bash
./gradlew test --no-daemon
```

Additional release build validation should include:

```bash
./gradlew :app:assembleDebug --no-daemon
scripts/check_apk_permissions.sh
```

## Known limits

- Some Redis/protobuf vehicle fields may still be unreadable because of missing keys, timestamp-only payloads, unconfirmed schemas, stale/cache data, or decoder gaps. This release changes the presentation and interaction flow; it does not claim complete vehicle data coverage.
- The wake acknowledgement delay is frame-based and may need tuning in noisy cars or on slower TTS engines.
- Vosk restricted grammar remains disabled for the real microphone ASR path; domain robustness still depends on open ASR plus NLU normalization.
