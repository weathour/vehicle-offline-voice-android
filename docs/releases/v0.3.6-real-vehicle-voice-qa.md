# v0.3.6 Real Vehicle Voice Q&A

Date: 2026-06-10
Scope: GitHub prerelease candidate for in-vehicle read-only Redis voice Q&A. Remote push and GitHub Release publication are authorized for this version.

## Why this release exists

The latest real-vehicle Redis inspection changed the app from a simulator-oriented read-only demo into a field-debuggable voice Q&A surface. The important change is that voice answers now follow the Redis keys and protobuf field positions observed on the vehicle, while preserving the safety boundary: the real-vehicle workflow reads and explains data only.

## Real-vehicle information updates and behavior changes

### Redis key contract

- Remaining range now prefers `DCU_INFO_St`, with `DCU_INFO` kept as a compatibility alias.
- Traffic light now prefers `Sensor_TrafficLightlist`, with `Sensor_Trafficlightlist` kept as a compatibility alias.
- SAM now prefers `Sensor_SAM`, with `Sam` kept as a compatibility alias.
- New read-only keys are included in the default snapshot: `Sensor_Lanelist` and `planned_trajectory`.
- Redis debug rows display the primary key plus aliases, so the field team can see whether a renamed key is being handled.

### Field decoding

- Vehicle speed now prefers `Sensor_Location.linear_velocity` field 8 and converts m/s to km/h. `BC_Veh_Spd` remains a fallback because field 1 on the live vehicle is timestamp-like.
- Battery now decodes timestamp, voltage, current, and SOC from `DCU_Battery_St` using the observed live order.
- Remaining range now decodes field 2 from `DCU_INFO_St`.
- Location now decodes timestamp, longitude, latitude, height, pitch, roll, heading, linear velocity, velocity components, acceleration, angular velocity, UTM position, and RTK flag.
- Obstacles now decode count, all repeated obstacles, nearest obstacle by XY distance, size, velocity, confidence, and optional lon/lat.
- Traffic light and lane list explicitly distinguish timestamp-only payloads from usable business data. The app no longer says “no traffic light” or “no lane” when only a timestamp was observed.
- `planned_trajectory` is parsed as UTF-8 point text and summarized by point count, first point, last point, and approximate length.
- `Sensor_SAM` now surfaces auto level, driving mode feedback, gear feedback, steering feedback, acceleration command, and SAM speed. If scene ID is absent, replies say the V2V/V2I scene cannot be determined.

## Voice interaction updates

### Added questions

- Redis/data health: “Redis 状态”, “数据健康”.
- Freshness: “数据新鲜度”, “时间戳状态”.
- Key diagnostics: “Key 诊断”, “缺哪些 Key”.
- Battery detail: “电池详情”, “电池电压”, “电池电流”.
- RTK and pose: “RTK 状态”, “车辆姿态”, “俯仰横滚”.
- Obstacles: “障碍物数量”, “最近障碍物”.
- Perception and planning: “车道线状态”, “规划轨迹”.
- SAM: “SAM 状态”, “SAM 反馈”.

### Modified answers

- Speed answers include the source field when available.
- Battery answers can give SOC only or detailed SOC/voltage/current.
- Traffic-light and lane answers include a caveat when business data is absent.
- SAM answers avoid claiming a collaboration scene when the scene field is absent.
- Status and Redis debug summaries include missing keys, decode errors, and timestamp-only keys.

### ASR/homophone adaptation

The parser and default command grammar now include field-test terms and common offline-ASR confusions, including Redis variants, RTK variants, SAM variants, trajectory variants, lane-line variants, freshness variants, and key-diagnostic variants.

## App UI updates

- The main page now has a “可问内容” section listing all supported read-only questions.
- Questions are grouped by basic vehicle state, localization/perception/trajectory, intelligent-driving warnings, SAM/cooperation, Redis diagnostics, and this release’s not-enabled items.
- The Redis debug page now shows freshness, aliases, timestamp-only status, battery details, RTK/pose, obstacle count/nearest target, lane, trajectory, and Sensor_SAM status.
- Redis debug rows for schema-unconfirmed AC, body, TPMS, DCU_INFO_2, and DCU_L2_St values are labeled as schema-pending and “仅调试参考”, so screenshots do not promote old mappings as stable vehicle truth.


## Review hardening after first code review

The first Autopilot code-review cycle requested changes. This release now also includes:

- Real microphone / real-vehicle mode rejects actionable control intents before state mutation or Unity action JSON emission. Preview/mock modes still keep their mock action path.
- Askable content now separates stable, caveated, degraded, and disabled capabilities. DCU_INFO_1 gear/parking, ACC/LKA, DCU auto-drive reasons, takeover, AC, temperature, door/body, and tire replies are degraded with schema-confirmation caveats.
- SAM summaries no longer say “无协作场景” when `scene_id` is absent. They say SAM was read but the V2V/V2I scene cannot be determined.
- `BC_Veh_Spd` timestamp-only payloads no longer hide missing business speed. Speed still comes from `Sensor_Location.linear_velocity` when available.
- Alias reads recompute the remaining snapshot deadline before each fallback key.
- The simulator Redis writer refuses mutating commands against non-loopback hosts unless the caller explicitly acknowledges writes.
- `DCU_INFO_1` gear/parking is now schema-pending because live field 1 is timestamp and field 3 is not trusted as parking until the vehicle-side schema is refreshed.
- Battery SOC no longer falls back to field 3, because live field 3 is current; SOC is field 4 only.
- Direct cooperation-scene replies now use the stronger no-`scene_id` evidence-insufficient wording.
- Redis debug rows now mark degraded AC, temperature, door/body, tire, intelligent-driving, ACC/LKA, auto-drive reason, takeover, and mixed warning rows as schema-pending debug references.

## Safety boundary

- The real-vehicle release remains read-only for Redis/protobuf vehicle data.
- Voice write/control actions are not promoted in the real-vehicle UI.
- This version is published as a GitHub prerelease with a debug APK asset. The real-vehicle workflow remains read-only.
