# v0.3.8 Wake TTS Tail Guard

Scope: GitHub prerelease candidate for field testing the wake acknowledgement timing fix after v0.3.7.

## Why this release exists

Field testing showed that the v0.3.7 acknowledgement `我在，请说` could be captured by the microphone after wake, causing ASR/NLU to hear the app's own prompt and fall back to `没有听清请再说一遍`. The command listening window was not too short: the real microphone mode still allows about 30 seconds after wake and up to about 30 seconds per utterance. The issue was the asynchronous Android TTS playback and prompt tail leaking into the microphone path.

## User-visible changes

- Wake acknowledgement in real microphone mode is shortened from `我在，请说` to `我在`.
- The app now waits for Android TTS playback completion before resuming microphone command capture.
- After TTS completion, the pipeline keeps the 8-frame tail guard, about 0.8 seconds, before accepting command audio.
- Wake acknowledgement logs now include measured duration, for example:

```text
TTS wake_ack=我在 durationMs=xxx
```

## Timing notes

- Audio frame size: 1600 samples at 16 kHz, about 100 ms per frame.
- Wake tail guard: 8 frames, about 0.8 seconds after TTS completion.
- Wake timeout: 300 frames, about 30 seconds.
- Max utterance length: 300 frames, about 30 seconds.

## Validation

Validated locally with:

```bash

scripts/check_apk_permissions.sh
```

## Known limits

- Android TTS duration depends on the device TTS engine and speech rate; this build records the measured duration in logs so field testers can verify real behavior.
- The tail guard may still need tuning for very loud speakers, vehicle cabin echo, or specific TTS engines.
- Redis/protobuf field coverage remains in interface-verification state and is not changed by this release.
