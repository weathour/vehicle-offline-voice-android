# Stage 3：上车测试 UI 与流程整理

日期：2026-06-08  
目标：上车后减少开发操作，让测试人员在手机上直接完成 Redis 连接、只读数据诊断和语音测试；通过后可迁移安装到车载屏幕。

## 1. 目标流程

现场流程应压缩为：

1. 手机连接车辆网络。
2. 打开 APK。
3. 填 Redis IP、端口、DB、可选密码。
4. 点击“测试 Redis 连接 / 解码”。
5. 看到 connected、decoded、missing、decodeError 和基础摘要。
6. 点击“启动车上语音测试”。
7. 用语音测试车速、电量、胎压、告警、协作场景、协作车数量等。
8. 通过后，把同一 APK 安装到车载屏幕或车载 Android 环境。

## 2. UI 调整原则

- 第一屏只服务上车测试，不再把 mock / 虚拟麦克风入口放在主流程里。
- 开发入口保留，但折叠到“开发调试入口”。
- Redis 配置自动保存，避免现场重复输入。
- 连接测试必须在启动语音前可单独执行，优先定位网络 / Redis / key / protobuf 问题。
- 语音面板继续显示唤醒、ASR、NLU、TTS 和只读车况，便于现场截图反馈。

## 3. 本次已落实

- 新增 `PRODUCT.md`，明确产品型工具 UI 的设计依据。
- 主 UI 改为上车流程：填写 Redis → 连接测试 → 启动车上语音测试。
- Redis 配置支持 Host、Port、DB、可选 Password，并自动保存。
- 新增连接诊断：显示 connected、decoded、missing、decodeError 和基础摘要。
- 开发 mock / 虚拟麦克风 / 清空日志入口移动到折叠的开发调试区。
- 删除阶段性过程文档，保留接口文档、架构文档、阶段二交接和测试记录。

## 4. 下一步建议

1. 在真实车端 Redis 上验证连接测试面板输出。
2. 若真实 key 名不同，优先做 key 映射配置，不急于改 decoder。
3. 增加“一键复制诊断信息”或“导出现场日志”按钮。
4. 根据车载屏幕分辨率再做一版横屏 / 大屏布局。
